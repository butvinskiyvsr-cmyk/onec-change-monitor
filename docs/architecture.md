# Архитектура

Проект строится как модульный монолит. Git остаётся источником истины, а приложение формирует индекс для быстрого поиска и анализа.

## Поток данных

`Локальный Git / Gitea → Git fetch → анализ коммита → классификация объектов 1С → Desktop-интерфейс`

История читается непосредственно из локальной копии Git нативным WPF-приложением. Если существует `origin/<ветка>`, приложение использует удалённую ссылку, поэтому после `git fetch` показывает актуальную историю, не выполняя `pull` и не изменяя рабочую копию. Merge-коммит сравнивается с первым родителем — это показывает изменения, внесённые в целевую ветку результатом слияния. Веб-проект сохранён как основа для будущего серверного режима. Постоянный индекс и очередь фоновых заданий будут добавлены после проверки модели данных.

## Несколько репозиториев

Все операции имеют `projectId`. Настройки путей выгрузки принадлежат проекту, поэтому одна установка сможет анализировать разные конфигурации и разные структуры каталогов.

## Обновления приложения

Планируемая схема: тег GitHub → GitHub Actions → GitHub Release → проверка версии → резервная копия → установка → проверка состояния → откат при ошибке. Автоматическая установка по умолчанию выключена.
